# Organic 闭运算的性能调研

> 更新：正式 Organic 默认采用矩形 `close=48`，使用四遍一维单调队列扫描；外扩为椭圆 `expand_x=48;expand_y=36`。下文保留此前圆盘 closing 的性能调查与算法比较，涉及圆盘逐行扫描的瓶颈不再代表当前 closing 实现。

调研日期：2026-09-17。目标是加快当前保留灰度覆盖率、使用精确离散圆盘的 Organic 模式。本文区分已由源码或文献确认的事实与尚未实现、需要基准验证的建议。

## 当前算法和语言

`native/assglass.cpp` 中的形态学、Gaussian 羽化、遮罩合成和权重转换已经使用 C++；`native/build.py` 使用 `-O2 -fno-fast-math` 编译。Python 负责参数、字幕选择、资源生命周期和视频流水线。将调度也改写为 C++，不能解决重复构建相同遮罩的问题。

圆盘定义为包含边界的整数像素中心集合，半径 `r=96` 时包含 28,917 个点。当前形态学将其拆成 193 条水平线段，各线段采用单调队列，单次算子约为 `O(Nr)`，其中 `N` 是工作图像素数。它已经避免了逐核点实现的 `O(Nr²)`，但仍会重复扫描很大的工作图。193 条线段只有 58 种不同半宽；这些数字按当前整数圆盘定义计算。

阈值只决定哪些字幕像素参与几何计算：通过阈值的像素仍保留 `coverage/255` 灰度值。因此，当前输入不是二值图。膨胀和腐蚀都使用常数零边界，所有算子完成后才裁剪到视频画面。

## 可选算法

| 路线 | 文献或官方实现确认的能力 | 对当前模式的适用性 |
| --- | --- | --- |
| van Herk / Gil-Werman | 通过双向递推和可分离处理，线段与矩形 min/max 滤波可在每像素常数次比较下完成，与核半径无关 | 可作为更规则、适合向量化的基础算子；精确离散圆盘不能直接换成水平、垂直两遍矩形滤波 |
| OpenCV 通用 CPU 形态学 | 完整矩形走行列分离，其他核进入按非零核位置计算的通用滤波器，另有 SIMD 路径 | 直接换成大圆核 OpenCV 调用不保证更快；需要基准测试 |
| 圆盘小核或十字分解 | 多次较小核操作可以提高性能，官方文档明确表示结果不总等于原圆盘 | 适合显式可选的近似模式，不能静默替换当前精确语义 |
| 欧氏距离变换 EDT | 二值圆盘膨胀、腐蚀可由精确距离图阈值实现；已有线性时间 EDT | 先二值化会丢失灰度覆盖率，不能直接替换当前模式 |
| 并行圆窗算法、GPU | 圆窗形态学已有适合独立像素并行的启发式分解研究；OpenCV CUDA 提供形态学接口 | 应在消除重复计算后再评估，包含传输、工作区、后端和数值验证成本 |

[van Herk 的 1992 年论文](https://www.sciencedirect.com/science/article/pii/016786559290069C/pdf?md5=722c8ff7350e6697adf355d40612f5a4&pid=1-s2.0-016786559290069C-main.pdf)说明了矩形和八边形滤波的快速递推方法；[Gil 与 Werman 的论文记录](https://cris.technion.ac.il/en/publications/computing-2-d-min-median-and-max-filters-2/)提供相关 min/max 滤波的常数时间结果。不能将这些结果外推为任意离散圆盘都能用两遍滤波精确处理。

[OpenCV 官方分派源码](https://github.com/opencv/opencv/blob/4.x/modules/imgproc/src/morph.dispatch.cpp)中的 `createMorphologyFilter` 仅在核全部非零时选择行列分离。[官方 `MorphFilter` 实现](https://github.com/opencv/opencv/blob/4.x/modules/imgproc/src/morph.simd.hpp)按核的非零位置做 min/max，并提供 SIMD 实现。此外，OpenCV 默认椭圆生成使用浮点取整，默认腐蚀边界也与本项目不同。若实验替换，应自己生成当前整数核，并明确使用零边界。

[scikit-image 官方圆盘文档](https://scikit-image.org/docs/stable/api/skimage.morphology.html#skimage.morphology.disk)明确区分完整圆盘与 `sequence`、`crosses` 分解；后两者不保证完全一致。同一页面的 `isotropic_closing` 文档将距离变换路线限定为二值输入。[Felzenszwalb 与 Huttenlocher 的论文](https://cs.brown.edu/people/pfelzens/papers/dt-final.pdf)给出线性时间距离变换算法，但一般灰度距离变换不能直接等同于本项目的平坦圆盘灰度闭运算。

[Moroto 与 Umetani 的 2023 年圆窗灰度形态学论文项目页](https://cgenglab.github.io/en/publication/pg23_morphology/)介绍通过圆的凸包进行启发式分解，并指出其像素独立计算适合并行硬件。本次已核对作者摘要，未完整取得正文，因此本文不对其误差界、特定半径精确性或实际加速倍数作保证。[OpenCV CUDA 官方接口](https://docs.opencv.org/4.x/dc/d66/group__cudafilters.html)支持单通道 float32 形态学，但接口存在本身不是本项目获得加速的证据。

## 建议的实施顺序

首先跳过可证明没有模糊作用的帧，并按完整输入复用未变化的字幕组遮罩。动态背景仍需用当前视频帧计算模糊；字幕遮罩不变不等于可以复用上一帧视频。

以下是依据本地源码提出、尚需实现和逐像素验证的精确优化方向：

1. **在 Gaussian 前使用字节覆盖率。** 阈值选择和 min/max 不会引入新的灰度等级；中间结果始终属于 256 个 `coverage/255` 值。可保存 `uint8_t`，在羽化前用同一表达式转回 float。工作图存储量可以从每像素四字节降至一字节；实际速度收益必须实测。
2. **复用相同半宽的水平滑窗。** 对同一输入行，58 种半宽对应的结果可以复用于上下对称核行。按一种半宽流式处理可限制内存，但组合方式和边界仍须验证。
3. **按算子缩小有效区域。** 当前使用最大 halo 工作图贯穿全部阶段。可以反向推导最终结果的依赖范围，减少无效扫描；不得在算子完成前简单裁剪到视频画面，以免改变离屏字幕扩张回画面的结果。
4. **在保留语义的前提下评估 SIMD、多线程。** min/max 的规则合并容易向量化；有状态单调队列可以与 van Herk 递推作实际比较。多线程还需受本项目原生内存预算约束。

近似圆盘分解或二值 EDT 应作为明确标注的可选方案，并与当前精确模式比较边缘、细小凹口、灰度覆盖率和视频稳定性。本文没有为任何尚未实现的路线宣称加速倍数。
